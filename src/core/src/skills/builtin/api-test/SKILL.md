# 后端接口自动测试（api-test）

用 http_request 对本地后端做结构化验证，产出用例级汇总表。

## 步骤

1. **提取接口清单**（不要凭空编）：
   - grep 路由定义定位真实接口：Express/Koa（`router.(get|post|...)`、`app.(get|post|...)`）、Nest（@Controller/@Get 装饰器）、Spring（@GetMapping 等）。
   - read_file 读控制器确认：方法 + 路径 + 参数（query/body）+ 鉴权方式（header/token/cookie）+ 前置中间件。
   - 用户点名了接口就只测点名的；没点名则测本次改动涉及的接口，不要全量扫。

2. **准备登录态**：接口要鉴权时，先用 http_request 调登录接口拿 token。凭证来源：用户提供的测试账号或 .env 里的既有测试凭证；禁止硬编码任何真实密码，拿不到凭证就问用户。

3. **逐接口执行用例**（http_request，注意它每次都走审批——把用例组织成尽量少的调用）：
   - 正常用例：合法参数 → 断言 2xx + 关键业务字段（code/data 结构）。
   - 边界用例（按需）：缺必填参 → 期望 4xx；错误格式 → 期望 4xx 不崩；伪造/过期 token → 期望 401，不漏鉴权。
   - 断言看实际响应原文，引用关键字段值作证据，不要只说"返回正常"。

4. **汇总表**：接口 | 用例 | 期望 | 实际（状态码 + 关键字段） | 结论。失败附响应摘录（截前几百字符）与定位建议（参数错？鉴权漏？逻辑 bug？）。

## 硬约束
- 只测本地环境（localhost/127.0.0.1）。目标 URL 指向外部环境时立即停止并向用户确认。
- 写操作接口（POST/PUT/DELETE）用低破坏性用例先行：测试数据带明显标记（如 e2e-test- 前缀），禁止删除/修改看起来是真实业务的数据；拿不准就先问用户。
- 禁止未读路由定义就照前端代码里的 URL 猜接口——前端引用的可能已过期。
- 接口行为与文档/预期不符时如实报告差异，不要为了"全绿"放宽断言。
