## 一、agent 主循环与控制流

「看似卡死 / 无输出 / 过早收尾」类症状的根因集合（2026-08 集中爆发后修复，多为架构接缝）：

1. **终结类工具缺 tool.end**（2026-08-06）：enter/exit_plan_mode 被 runAgent 按名拦截，yield tool.start 后直接跳 final、从不 tool.end → 前端 ToolCard 永远「运行中」像卡死。修：终结分支补发 tool.end。
2. **busy 卡死吞输入**（2026-08-06）：setBusy(false) 只在最后一行，任何未捕获 reject 都让 busy 恒 true，之后输入全部静默 no-op。修：submit 改 try/finally + 代际守卫复位；abort 加 8s 安全网。
3. **resume 孤儿 tool_call + 错误 final 被吞**（2026-08-06）：中断进程时 tool_calls 已落盘、结果未落盘 → 恢复时 API 400；错误 final 又被「正文已流式」去重逻辑清空。修：repairOrphanToolCalls 补占位；final.text 按 streamedAnyText 决定转发。
4. **工具执行段整体无 catch**（2026-08-07）：外层 try 只有 finally，任意 throw 逃出 generator → final 永不发 → 前端永久 busy。修：外层补 catch 兜底 yield final，消费方 for await 双保险。
5. **stall 重试门控过严**（2026-08-07）：要求「三个 buffer 全空」才重试，但工具轮几乎都有前导文案 → 永不重试等满 120s 超时。修：放宽为「没拼出完整 tool_call 就重试」，重试前 text.reset 让前端丢弃半截文本。
6. **TOOL_DIGEST 误拦总结轮**（2026-08-11）：初版用 looksComplete 关键词判「空手收尾」，关键词太窄 → 误拦真实总结 → 连发 2-3 个 final。修：改用文本长度门槛（<30 字符才算空手），长总结绝不拦。
7. **busy 时输入静默丢失**（2026-08-17）：webview 先清输入框再调 host，host 静默 return → 用户输入彻底丢。修：busy 分支改排队（inbox steering，轮边界送达）。教训：**「先清 UI 再调用」模式下，被调方静默 return 都是丢数据**。

其它控制流铁律：

- **generator 包装三犯铁律**（三次实锤：9bda588 / 直答通道 / w7ez）：包装 async generator 工具时，包装器本身必须是 `async function*` 且用 `yield*` 委托透传——普通 async 函数返回 generator 会被执行器 stringify 成空壳 `{}`，命令明明执行成功模型只见空对象。
- **直接单测 background 工具须再 next()**（2026-08-20）：run_in_background 的 execute 是 async generator，只取首个 yield 时 close 监听未注册、status 永远 running；测试须补一次 `gen.next()` 模拟框架驱动。
- **Promise.race 清理必须进 finally**（2026-10-26）：race 后裸写 clearTimeout/removeEventListener，竞争方 reject 时清理被跳过 → 定时器泄漏挂住进程退出（实测 122s vs 1.9s）。诊断信号：测试跑完不退出 → 查挂起的 timer/listener。
- **有意设计勿当缺陷**（2026-09-11 用户确认）：审批栅栏无 TTL、后台锁 check-then-act 都是刻意的（单人本地工具），评估/修复时勿再顺手加固，相关测试注明「有意设计勿修复」。

## 二、上下文工程：压缩·归档·召回·多模态

**召回体系**（2026-08-24 落地）三条硬约束：

- 摘要槽双段：`⟦DSC:ARCHIVE-INDEX⟧` 实体索引由代码正则确定性提取、**永不送 LLM 压缩（索引无损是硬约束）**；`⟦DSC:ARCHIVE-NOTES⟧` 叙述可自收敛。
- 侧车存档：超长工具结果在**脱敏后、截断前**落盘 `<会话目录>/tool-outputs/`——位置顺序是安全红线（顺序错了=明文绕过脱敏写盘）。
- recall 首查词引导：模型会拿工具名（read_file）当查询词，迭代 6 次才命中——description 里必须写「首查策略：具体实体词、禁工具名/泛词」。

**fence 注入的锁语义**（2026-09-03 勘误）：「会话首锁」只在同一 message 数组被二次 setup 时触发；正常流每轮重建 message[0]，**源变化在同会话下一条消息即生效**（击穿一次缓存），不是「下个新会话」——注释曾过宽，已修正。双层表述：run 内零漂移=锁的硬保证；跨 run 稳定=确定性重建达成。

**多模态（贴图）**（2026-08-27→09-14 演进）：

- 名字启发式判定模型 vision 能力必误判（deepseek-v4.1-flash 原生多模态但名字无 vision 标记，真实事故：模型去找 OCR MCP）。终态=零配置乐观直发 + 400 自学习降级（能力缓存 model-capabilities.json）+ env 一票否决。
- base64「三不进」红线：estimateTokens stringify 分支、实体索引正则扫描面、压缩辅助摘要批——任何触达消息内容的改动先过 contentParts 提取文本。
- 两道 string 闸：text-only 消费面永远收 string，数组形态只出现在 vision 开启的主模型 wire 上（数组哪怕纯 text parts 对 text-only 端点也是未验证表面）。

## 三、缓存与 token 成本

**计费口径**（先看这个再判断「贵不贵」）：

- DS 官网「消耗 token」= total_tokens **全额**（含缓存命中），实际计费：命中 ×0.1、miss ×1、输出 ×1。800w total、94% 命中的任务等效计费仅 ~142w。**官网数字≠花的钱**。
- 分时计价（2026-09-10 起）：flash 高峰（8:30-16:30）价格 ×2；缓存 miss 是 hit 的 **50 倍**（高峰 ¥2 vs ¥0.04/M）。降本最粗杠杆：**大批量任务排空闲时段直接省一半**。
- token 消耗根因层级：**轮数（自回归放大器）> 跨 run 重复背负 > 单轮上下文规模 > 压缩时机**。

**DS 缓存机制实测结论**（四组受控实验，2026-09-08）：

- 首个缓存块 = **[tools + system + 摘要槽] 打包的 ~11.3K token**，块内任何字节分歧 = 整块全失（不是字节级前缀二分）。
- message[0] 尾部任何注入漂移（语言翻转/outputStyle/skills·memory 目录变化）和工具表任何变化（版本/MCP/env 门控），代价都是整个固定前缀 re-prefill。
- 跨会话/跨进程保留字节级相同前缀的缓存（同题重跑 0% → 99.8%）；fresh-session 真实 15% 命中的根因是真实会话前缀存在字节分歧（记忆/技能注入演化），结构性、~¥0.02/会话、不值得治。
- **并行子代理同 hash 互不命中** = 并发首发竞态（缓存写可见性秒级延迟）→ 并行 spawn N worker = N 份全价首轮，单人本地可接受；串行同 hash 子链 95-98% 正常。

**子代理首轮缓存 0% 根因与修复**（2026-10-12）：子代理 system 段编入任务描述 → 每个子 run 的 sysHash 各不相同 → 前缀在 system 段即分叉。修：task/角色/续跑说明全部挪出 system、并入首条 user 消息，system 只留恒定内容。守门断言「system 不编任务」已钉进测试。

**reasoning_content 剥离**（2026-09-10，v1.0.62-63）：历史轮 reasoning 占活动窗口 prompt 的 29.2%、跨轮重发负担 25%——出口单点默认剥全部历史 assistant 的 reasoning_content，浅拷贝不碰落盘。
**踩雷**：DS thinking 校验实为两档——「最后一条非 system 消息是 assistant」（草稿续写）时任何缺 reasoning 即 400（严格档）；正常轮（末条 user/tool）剥了也没事。产品里命中严格档的是收尾守护轮（nudge 跟在草稿后）——根治法：nudge 跟在 assistant 草稿后时角色改写为 user，请求以 user 结尾落宽松档。
另注意：草稿可能天然无思考字段（round reasoning=0chars），「保留全量」也救不了它——必须靠角色改写。

**缓存塌方治理**（2026-11-04，M1/M2/M3-1）：全天 trace 实证三处塌方 ≈¥1.0/天（当天账单 23%）。落地：trace 事件 context.check/decay/llm.contextDowngraded 埋点（M1）；injectMemory 会话级快照 Map 防每轮重读漂移（M2）；decay 不再早退、改写历史后续走压缩（M3-1）。sumHash=摘要槽 hash 钉死用于排除根因（写槽必变 sumHash）。

**诊断入口**：trace jsonl 里 llm.response 的 usage 是真实计量（llm.request 的 prompt_tokens 是本地估算别拿来对账）；前缀指纹 toolsHash/sysHash/sumHash 埋点二分定位分歧；分析脚本 scripts/cache-fingerprint-report.ts。压缩事件名是 `session.summary`，grep compact 搜不到。

## 四、测试与 CI

**node:test v22 并发随机挂**（2026-10-27 根治）：裸 stdout 与 v8 序列化结果帧同管道，stdout 写非 ASCII（UTF-8 ≥0x80）帧长解析为负（nodejs/node#64061，v22 无上游修复）→ 随机挂整文件、总测试数虚低。修：tests/ascii-stdout.mjs 预载（npm test 自动注入 stdout 转义）。上游修复进 v22 后可退役。

**全量 flake 家族判据**：「单跑恒绿、全量随机挂、换着文件挂」= 测试基建/竞态类 flake，先单跑确认再判断，勿当回归排查：

- listen 家族全量假超时（2026-11-19 修毕）：根因=Windows Defender 对刚写完的 tmp 文件瞬时持锁，裸 fs.rename 撞 EPERM → 登记失败 → 测试空转到 60s。修=renameWithRetry（只重试 EPERM/EACCES/EBUSY、8 次退避 800ms 封顶）。**实测教训：退避预算要按饱和负载下的锁时长设计，不能按空载直觉**（首版 375ms 被全量并行打穿）。
- 映射表丢更新（2026-11-11 修）：三张 JSON 映射表「读→改→写」无锁，并发 rename 后写覆盖前写。修=按文件路径 Promise 链串行写。**信号：「单跑恒绿全量恒挂且换着挂」= 查共享文件的读改写**。
- `npm test | tail` 管道会吃掉退出码（tail 的 exit 0）——验收必须落盘读文件：`npm test > log 2>&1; echo $?`。

**CI（GitHub Actions，windows-latest）坑集**：

- runner TEMP 是 **8.3 短名**（RUNNER~1），native realpath 是长名——同一文件两种字符串，路径前缀比较必误判。本地永远复现不了，只有 CI 抓得住。修法：两边统一 `realpathSync.native` 再比。
- runner 是白板：**无全局 git 身份**——测试建临时仓必须仓库级 `git config user.*`。本地模拟法：`GIT_CONFIG_GLOBAL=空文件`。
- vscode-ripgrep postinstall 从 api.github.com 拉二进制，Azure runner IP 共享限流会 403——install 步骤注入 `GITHUB_TOKEN`（勿删）。
- commit message 勿写字面 `[skip ci]`（GitHub 会整个跳过 workflow）。
- 改 workflow 文件需 token 带 workflow scope（gh auth refresh -s workflow）。
- 本机全绿 ≠ CI 绿（白板差异 + 2 核慢机）；push 后必须监测 CI 到终态、红也立即报（用户 2026-11-12 要求）。

**evals 试点**（2026-09-10 建，tests/evals/ 三套，真 API 不进 CI）：任务级基线 / 压缩质量 / 风险分类器。教训：

- 关键词判定有子串误匹配坑（「能用」匹配到「不能用」把答对的误判 FAIL）——否定语境要整短语判定；**判定器也是要审的代码**。
- fixture 写在 TS 模板串里 `\n` 反斜杠会被吃掉，产物须写 `\\n`；fixture 是纯 JS 不得混 TS 语法。
- 跨压缩存活题设计要点：盘上可重推导的任务对槽损坏天然免疫——要咬住压缩语义须加「对话独有交付物」（只存在于 prompt 的事实，不上盘、不进实体索引）。

**tsx 双模块实例坑**（2026-08-18）：tsx 按 specifier 字符串判模块身份，`@/llm/model.ts` 与 `../src/llm/model.ts` 指向同一文件却是两个实例——setActiveProvider 注入静默失效、**继续打真实付费 API**（产生过小额真实消耗）。修：测试/探针的 import specifier 必须与 core 内部消费方同形式（统一 `@/`）；换装后先断言 activeProvider.id 再跑。

## 五、发版与包管理

**发版三件套**（缺一被点名）：版本号 bump + src/vscode/CHANGELOG.md 条目（主题句+加粗要点）+ npm run package。

**版本号规则**（两次纠正后钉死，2026-11-04）：

- vsix 版本 = **Marketplace 线上 +1**（`npx vsce show` 直连可查），本地打包/安装状态不参与。号链分叉（本地打过未上架）的正解=重编+合并 CHANGELOG，勿跟本地链续号。
- CLI 版本 = npm 线上 +1，**永不与 vsix 对齐号**（两线各计数，号差≠落后）。
- 改 version 用正则（perl -pi）勿 stringify 重排 package.json。

**发版内容口径**（2026-11-05 用户两次纠正）：未过验收的功能**不进 main、不进 vsix**；main 只收修复线；功能线可提前吃修复线（单向无害），过验收后独立发版。源码直跑验证、验收腿过了再打包。

**npm 分段发布流**（2026-11-12 起）：GAT 只能 stage——`npm stage publish` → validating → staged → **网页控制台批准**（CLI approve 对 GAT 恒 404=权限伪装勿当 bug，换 key 无用）→ 批后 stage list 清空、shasum 对照验证。

**vsix 瘦身规范**（2026-08-12 定，9.08MB→3.78MB）：esbuild bundle 纯 JS 依赖，只 external vscode + vscode-ripgrep；dependencies 只留 vscode-ripgrep，其余全 devDependencies；发布构建 minify 剥注释（防源码注释进产物，勿去掉 minify）。新增运行时依赖默认进 devDep（会被 bundle），只有原生二进制才进 dependencies。

**CLI bundle 陷阱**：dist/cli.mjs 是 esbuild 单文件、**内联 core 全部源码**——改 core 后 CLI 必须重建才生效（vscode 扩展同理要重打 vsix）。esbuild 把中文转成 `\uXXXX` 大写 hex 转义——**bundle 里 grep 中文必 0 命中**，核验产物要么搜字符串字面量/ASCII 锚点、要么读文件反转义再搜（探针记得 toUpperCase）。

**包管理器坑**：

- pnpm --filter 路径相对 cwd——cd 进 src/vscode 打包后 filter 静默失配且 **exit 0 假成功**；装完必须 ls node_modules 验证。
- pnpm workspace + vsce 固有不兼容（vsce 顺符号链接追到 .pnpm store 越界拒绝）——src/vscode 单包用 npm 扁平重装。
- 本机全局 npm（D:\npm\node_global）经 shim 优先于 node 自带版，npm 12 与 node 22.12 错配出警告且疑似全局装静默失败——必要时直接用 bundled npm-cli.js。
- MCP 配置勿用 `npx -y`（本机 npm/npx 历史反复坏），用「良安装 + node 直跑 cli.js」+ `${dataDir}` 占位符。

**仓库/品牌**：已全量改名 DeepSeeker-Code 族（包名/目录/扩展/命令），但 `DEEP_SEEK_*`（带下划线=厂商）变量与 `deepseek-v4` 模型 id 保留勿改。

## 六、并行会话与同仓竞态

两个 agent 会话（或两个 Claude 窗口）共享同一工作树时的连环坑（2026-10-27 两次实锤）：

- `git add -A` 式提交会**吞对方改到一半的磁盘态**（对方升的版本号/CHANGELOG 被扫进我的提交）；提交信息只反映「以为 add 了什么」。→ **只按显式路径 add**，commit 后 `git show <hash>:<file>` 复核关键文件。
- 对方重建 dist 时会把我未完成的代码打进它的 vsix（esbuild 不报错，TDZ 是运行时错）。→ 打包前 `git status --short` 查是否有他人未提交改动，有就先提示竞态。
- 版本号先读盘上 package.json + git log 再定 bump（磁盘可能已被对方改掉）。
- 工作树里冒出自己没改过的文件：一律不碰、不提交、不还原，留给对应会话。
- 发现错位优先评估内容完整性，内容齐就别 rebase 改哈希（对方会话还活着时等于埋雷）。

## 七、VSCode 扩展

**webview 两条消息通道**（2026-08-07）：sink 包裹通道（`{type:"evt",evt}` → handleEvent，回放行/流式/tool 事件）与直发通道（postMessage → onMessage，sessionReset/state/sessions）。新增消息类型 handler 放错通道 = 静默失效（实锤浪费过一次打包）。

**sticky 钉顶五坑**（2026-10-13→10-27 五轮修复）：

1. sticky 约束矩形是**容器 padding 内缘**非可视顶——容器须 padding-top=0、钉顶元素 margin-top=0。
2. 钉住块遮挡底色必须与 body **同源 CSS 变量**（外部猜变量必对不上）。
3. 通栏=stuck 态负 margin 抵消容器侧 padding（与 padding 值耦合）。
4. **滚动打标的 class 只准动 paint 不准动 layout**——`.stuck` 改 max-height 会自指震荡（打标阈值=滚动位置，布局跳变→浏览器钳回→再打标），贴底跟随永失。
5. clip-path 钳高也不行（行盒悬空成空白窗）。**终解：行盒不参与钉顶，用 height:0 的 sticky 占位卡（pin-holder）悬挂克隆卡片**——滚动⇄布局解耦由构造成立。

**贴底跟随**（2026-10-13）：必须「DOM 变更前测贴底、变更后落底」（stickNow/stickTo 原语）；变更后测会被新行自身撑过阈值→门禁自锁永不自愈。`scroll-behavior:smooth` 是共犯（动画期间 scrollTop 滞后）——已移除勿恢复。user 行发送即落底。

**activeTextEditor 聚焦陷阱**（2026-10-29）：点进 webview 瞬间 activeTextEditor 变 undefined 且 onDidChangeActiveTextEditor 带 undefined 照发——「提交时现读编辑器态」必坏。修：事件驱动持续快照 + `ed === undefined` 一律 return + 只在真切编辑器时作废旧快照。

**「改动没生效」诊断纪律**（2026-10-14 教训）：先 grep 安装目录 dist 产物的新代码特征确认产物新旧；产物是新的立刻转向查自身逻辑（尤其「条件从没满足过」的恒假分支——.stuck 判定 `rect.top <= 1` 恒假导致钉住态从未渲染，六层静态证据全对仍误诊两次）。本机扩展目录在 D:\catch\vscode\extensions（非默认）。

**工作区隔离键分桶**（两段修复史）：会话/trace/undo/用量按 deriveWorkspaceKey(cwd) 分桶，键在 config 模块**加载期算定一次**。坑：extension 入口的 core 静态 import 链抢在 chdir 前求值 → 键钉死在 VSCode 安装目录（78/98 run 数据错桶）。修：activate 注入钩子后无条件重导。**红线：extension 入口勿新增对 core 的运行时静态 import**。

**动作面板杂坑**：dynamic 建元素必查 id/className 与 CSS 选择器两边对齐（漏 className 一条 CSS 不命中，面板挤没消息区）；flex 子项滚动列表必须 `min-height:0`（默认 auto 拒绝收缩=假性不可滚）；「点击→原地重绘」的浮层，外点关闭委托必须配抑制标志（重绘把被点元素摘出面板，contains 误判直接关窗）。

**TS 工具**：typescript 不是 core 运行时依赖（VSCode 扩展 bundle 进去可用，CLI 未必装）——靠 validateEnvironment 自隐藏；Windows 大小写不敏感 FS 上 TS1261 伪报，治法=查询路径用 native realpath + forceConsistentCasingInFileNames 置 false。

**diff 视图**（2026-08-19）：diff 纯 UI 层从 args 计算（不回灌模型浪费 token、不依赖 git）；修改前内容 = 工具执行前 host **同步**快照（异步读与工具自身读写有竞态）；fileDiff.ready 事件必须在 tool.start 转发之后发（webview 要先登记才能亮按钮）。

**webview 模块裸测法**：桩 acquireVsCodeApi + pathToFileURL 直 import，纯逻辑可跑断言不用起 VSCode。

## 九、Windows·编码·字符陷阱

- **Edit 工具 × emoji**（2026-10-08）：带 emoji/✓/✕ 的行匹配失败（不可见变体选择符 U+FE0F）；new_string 里写 `\uXXXX` 转义落盘变 **NUL 字节**（传输层吞转义）。修法：perl -i 用 ASCII 锚点容错吞掉 emoji 字节；源码里生成特殊码点用 String.fromCharCode；写完 `od -c` / perl 扫 NUL。
- **孤立代理对 400**（2026-11-13 事故）：按 UTF-16 码元裸 slice 截断劈开 emoji 代理对 → 孤立 \udXXX 转义 → DS 400「unexpected end of hex escape」（措辞像网络截断，极具误导性）。磁盘文件干净（毒是装载时现切）→ 扫文件找不到；破案法=**用真实装载器离线重建 body 再扫**。修：sliceHeadNoSplit/sliceTailNoSplit 防劈对（覆盖全部切点）+ surrogateGuard 出口双通道净除终防线。**新写任何按长度截断入 API 消息的代码必须用这对助手**。
- **esbuild 中文转义**：bundle 里中文=大写 hex `\uXXXX` 转义文本——字面 grep 中文必 MISS（连查 3 轮全 MISS 差点误判「改动没进包」）。探针生成 hex 要 toUpperCase。
- **curl 中文请求体**（2026-10-22）：Git Bash 内联中文 JSON 必被 GBK 弄坏成 400 invalid unicode（连吃 10 个 400 险些误判端点故障）——API 测试体只用 ASCII 或 `curl -d @file`（UTF-8 写盘）。
- **NotebookEdit × 中文**（2026-10-29）：含中文的 new_source 会被逐字拆行写坏 .ipynb——改 notebook 一律 Write 整文件重写 + 三连验证（json.load → 逐格 ast.parse → 业务断言）。
- **块注释内 glob 示例**（2026-08-19）：`/** ... */` 里写 `'**/*.ts'` 时 `*/` 提前终止注释 → 一堆 TS1109 且首错在注释中间极难定位。示例改写成不含 `*/` 序列的形式。
- **VBS 中文路径**：含中文的 VBS 必须存 GBK 编码（UTF-8 被 wscript 读成乱码）；schtasks /TR 纯 ASCII（所以 VBS 壳放用户全局目录）。

## 十三、排查与评审方法论

从多次评审/事故排查中沉淀的通用方法：

1. **地面真值勿用代理**：机制/成本结论必须用系统真值（trace usage、三段指纹、价表核对），不能用重算代理；差分指标（miss−Δprompt）比绝对值抗干扰。
2. **报错文本也是转述**：服务器报错措辞（「unexpected end of hex escape」像网络截断）别当字面事实——先本地复现出毒字节再说。假模型名 POST 真实 body 是零成本好探针（解析先于模型校验）。
3. **并行配对伪影**：并行爆发下 ts 就近配对会把同一响应配给多个请求——聚合稳健、逐轮标签不可信。
4. **产物排查纪律**：「改动没生效」先确认产物新旧（grep dist 特征码），产物新就查自身逻辑（恒假分支）；bundle 里的中文/标识符都被转义或改名，锚点只能用字符串字面量。
5. **数据源核对**：报告渲染的数据源是不是运行时那个对象、时序对不对（门在提交前跑=看不见 untracked）。「报告说真跑了」可用 target/ mtime 指纹证伪。
6. **断言前先看内部**：断言「文件按 X 分」前必须打开路径函数看内部归一化（trace 共文件设计的误判教训）。
7. **验收结论口径**：全量测试有已知 flake 家族时，验收要么注明「唯一失败=已知 flake」要么先治；exit code 与输出文件内容必须都看。
8. **评审勿翻案定论**：三轮以上收敛的结论（缓存 1/50、D1 不猜原因、有意设计清单）再遇同类直接引用，勿重新论证。
